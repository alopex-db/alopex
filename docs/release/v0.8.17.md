# v0.8.17 release notes (draft)

This is the working release candidate. It has not been published or qualified
for release. The authoritative implementation, acceptance, RC and post-release
main integration tracker is [#690](https://github.com/alopex-db/alopex/issues/690).

## Accepted preparation

- Bounded old-writer → candidate-reader checks have separate SQL VECTOR, raw
  VECTOR, columnar codec, Arrow representation/dimension and language-direction
  cases. Historical Python API behavior uses explicit case IDs.
- Load and performance measurements are excluded from ordinary CI and require
  a separate manual run with an owning issue and resource budget.

## Planned changes — not yet accepted

- Public Rust configuration compatibility: #696.
- CSV NULL/empty preservation, columnar export and VECTOR Parquet: #691, #692, #693.
- HNSW truncate/cache and transaction startup: #677, #681, #684.
- Byte-bounded KV paging, parser binding and EXPLAIN accuracy: #678, #680, #679.
- WAL capacity reclamation and bounded oversized atomic batches: #683, #682.
- Core/Python latest handling, report publication and optional Intel delivery:
  #688, #431, #686.

Replace this list with accepted behavior and exact evidence as each change is
integrated. Inclusion here is not evidence that an issue is fixed.

## Compatibility and distribution — to finalize

Existing V2 database readers remain required. Direct database upgrade and
external export/import are separate contracts. Document supported Rust source
patterns separately from runtime compatibility, and describe any necessary
migration without implying recovery of already-lost CSV/Parquet information.

Linux x86_64, Windows x86_64 and Apple Silicon remain the intended required
release targets. Intel delivery policy is owned by #686 and is not implemented
by this version preparation alone.

- Public verification and report URLs: pending publication.
- Post-release main merge/ancestry and CI: pending; #690 remains open until done.
