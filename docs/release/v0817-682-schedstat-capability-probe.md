# #682 bounded schedstat capability probe

This source-only candidate adds a conditional step to the existing inventory job in `alopex-performance.yml`. The intended `workflow_dispatch` input is `issue_number=682` with `qualification_mode=false`, `sql_four_case_mode=false`, and `wal_cost_mode=false`. It does not change the #804 inventory collector, qualification controller, container profile, kernel setting, or security policy.

The nonroot helper temporarily pins only its own process to one CPU in its existing allowed affinity set; the child inherits that affinity. It restores the original affinity and terminates/reaps the child in `finally`, including when sampling fails. The CPU contention lasts about 0.2 seconds, with child lifetime and cleanup bounded below two seconds. If process-local affinity cannot be obtained or set, the fixed public result is `SCHEDSTAT_AFFINITY_UNAVAILABLE` and no child sample is claimed. The helper then reads `/proc/self/schedstat` and `/proc/sys/kernel/sched_schedstats`, then samples its own and a short-lived sibling Python process's schedstat counters before and after bounded CPU activity. It records separate deltas for runtime, runqueue-wait (the second field), and timeslices, and classifies each sample as missing, unreadable, zero, advancing, or static. Raw counters and the kernel setting are written only to a mode-0600 temporary JSON file, encrypted to `native-inventory-export/schedstat-private-evidence.cms` with the repository evidence certificate, and removed. The uploaded console/public JSON contains only the fixed `SCHEDSTAT_CAPABILITY` case, `not_assessed` qualification state, and one allowlisted code. It contains no host identity, process ID, machine path, or raw counter.

Positive checks: positive per-process runqueue-wait deltas for both self and sibling yield `SCHEDSTAT_ADVANCING`, including when `/proc/sys/kernel/sched_schedstats` reads `0`. The sysctl value is retained only as private context; it does not gate the per-process method. CPU runtime or timeslices may move while runqueue-wait legitimately remains zero when there is no contention; that case yields the distinct fixed code `SCHEDSTAT_WAIT_UNPROVEN`. Zero, missing, unreadable, and static counter cases produce their corresponding fixed codes. Negative checks use fake `/proc` files and verify CPU-only movement, an absent or malformed counter, and a nonadvancing counter cannot be reported as runqueue-wait proof. The existing inventory artifact upload retains the encrypted result even if the probe step fails. No outbound network request, Docker operation, privilege change, kernel sysctl write, or container construction is required by this step. This is short-lived scheduling of the probe’s own processes, so it is not strictly read-only.

The helper process and child sample are bounded below two seconds in normal operation, with short cleanup timeouts. Its private JSON and ciphertext are small; the source worktree is constrained to 50 MB. The probe is an independent observation of one inventory job only. The #682 diagnostic must repeat the schedstat capability check in its own same-job run before accepting a kernel measurement method. A passing inventory probe alone does not qualify that future kernel or authorize WAL cost measurement.
