# #682 read-only schedstat capability probe

This source-only candidate adds a conditional step to the existing inventory job in `alopex-performance.yml`. The intended `workflow_dispatch` input is `issue_number=682` with `qualification_mode=false`, `sql_four_case_mode=false`, and `wal_cost_mode=false`. It does not change the #804 inventory collector, qualification controller, container profile, kernel setting, or security policy.

The nonroot helper reads `/proc/self/schedstat` and `/proc/sys/kernel/sched_schedstats`, then samples its own and a short-lived sibling Python process's schedstat counters before and after bounded CPU activity. It records separate deltas for runtime, runqueue-wait (the second field), and timeslices, and classifies each sample as missing, unreadable, zero, advancing, or static. Raw counters and the kernel setting are written only to a mode-0600 temporary JSON file, encrypted to `native-inventory-export/schedstat-private-evidence.cms` with the repository evidence certificate, and removed. The uploaded console/public JSON contains only the fixed `SCHEDSTAT_CAPABILITY` case, `not_assessed` qualification state, and one allowlisted code. It contains no host identity, process ID, machine path, or raw counter.

Positive checks: a `1` kernel setting with positive runqueue-wait deltas for both self and sibling yields `SCHEDSTAT_ADVANCING`. CPU runtime or timeslices may move while runqueue-wait legitimately remains zero when there is no contention; that case yields the distinct fixed code `SCHEDSTAT_WAIT_UNPROVEN`. Zero, missing, unreadable, disabled, and static cases produce their corresponding fixed codes. Negative checks use fake `/proc` files and verify CPU-only movement, an absent or malformed counter, and a nonadvancing counter cannot be reported as runqueue-wait proof. The existing inventory artifact upload retains the encrypted result even if the probe step fails. No outbound network request, Docker operation, privilege change, or container construction is required by this step.

The helper process is bounded to roughly one second and a short child cleanup timeout. Its private JSON and ciphertext are small; the source worktree is constrained to 50 MB. The probe is an independent observation of one inventory job only. The #682 diagnostic must repeat the schedstat capability check in its own same-job run before accepting a kernel measurement method. A passing inventory probe alone does not qualify that future kernel or authorize WAL cost measurement.
