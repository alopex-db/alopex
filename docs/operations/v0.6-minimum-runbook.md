# v0.6 Minimum Operations Runbook

This runbook covers the minimum operational steps needed to run `alopex-server`
in practical v0.6 deployments. It is intended for operators who need to confirm
server limits, handle overload, take and restore snapshots, and perform first
response diagnostics.

Examples assume the default HTTP bind address (`127.0.0.1:8080`) and no
`api_prefix`. When `api_prefix` is configured, prepend it to the paths below.

## Default Operational Values

| Setting | Default | Operational meaning |
| --- | --- | --- |
| `http_bind` | `127.0.0.1:8080` | HTTP API bind address |
| `grpc_bind` | `127.0.0.1:9090` | gRPC API bind address |
| `admin_bind` | `127.0.0.1:8081` | Admin bind address |
| `admin_allowlist` | `[]` | Required when `admin_bind` is non-loopback |
| `data_dir` | `./data` | Storage directory |
| `api_prefix` | `""` | Optional route prefix |
| `auth_mode` | `{ type = "none" }` | No HTTP auth by default |
| `query_timeout` | `30s` | Per-query timeout |
| `max_concurrency` | `64` | Maximum admitted concurrent HTTP requests |
| `max_queue_len` | `256` | Maximum queued HTTP requests under backpressure |
| `max_request_size` | `104857600` | Request body limit, 100 MiB |
| `max_response_size` | `104857600` | JSON response body limit, 100 MiB |
| `session_ttl` | `300s` | Session TTL |
| `metrics_enabled` | `true` | Prometheus metrics enabled |
| `tracing_enabled` | `true` | HTTP tracing enabled |
| `audit_log_enabled` | `true` | Audit logging enabled |
| `audit_log_output` | `{ type = "stdout" }` | Audit log sink |
| `ALOPEX_MEMORY_LIMIT_BYTES` | `268435456` | SQL memory control limit when unset, 256 MiB |
| `ALOPEX_MEMORY_SPILL_POLICY` | `fail_fast` | Reject over-limit SQL memory use by default |
| `ALOPEX_MEMORY_SPILL_DIR` | unset | Required to enable disk spill policy |

`max_connections` is accepted as a legacy config alias for `max_concurrency`,
but new configuration should use `max_concurrency`.

## Overload Behavior

Admission control first tries to acquire one of `max_concurrency` permits. If no
permit is available, the request waits in the admission queue. When the queue
length would exceed `max_queue_len`, the new request is rejected immediately.

Rejected requests return HTTP `503 Service Unavailable`:

```json
{
  "error": {
    "code": "SERVER_BACKPRESSURE",
    "message": "server request queue is full",
    "correlation_id": "<request correlation id>"
  }
}
```

Requests that were already admitted continue running; queue overflow rejects only
the new overflow request.

## Backup

Start a backup:

```bash
curl -sS -X POST http://127.0.0.1:8080/api/admin/backup
```

Response:

```json
{
  "handle": "<uuid>",
  "location": "./data/.lifecycle/backup/ts-...",
  "state": {
    "status": "running",
    "started_at_ms": 1760000000000,
    "finished_at_ms": null,
    "progress": {
      "percent": 0,
      "bytes_processed": null
    },
    "reason": null
  }
}
```

Poll the backup handle until `state.status` is neither `running` nor `queued`:

```bash
curl -sS http://127.0.0.1:8080/api/admin/backup/<handle>
```

Successful completion has `state.status: "completed"` and `progress.percent:
100`. A failed backup has `state.status: "failed"` and `state.reason` populated.

Backup writes a snapshot under `data_dir/.lifecycle/backup/ts-...`, writes
`data_dir/.lifecycle/backup/latest`, and verifies `snapshot.manifest` before the
operation completes.

## Restore

Restore from an explicit snapshot path:

```bash
curl -sS -X POST http://127.0.0.1:8080/api/admin/restore \
  -H 'content-type: application/json' \
  -d '{"source":"./data/.lifecycle/backup/ts-..."}'
```

Restore from the latest known backup or archive:

```bash
curl -sS -X POST http://127.0.0.1:8080/api/admin/restore \
  -H 'content-type: application/json' \
  -d '{}'
```

Response:

```json
{
  "handle": "<uuid>",
  "state": {
    "status": "running",
    "started_at_ms": 1760000000000,
    "finished_at_ms": null,
    "progress": {
      "percent": 0,
      "bytes_processed": null
    },
    "reason": null
  },
  "metadata": null
}
```

Poll the restore handle until `state.status` is neither `running` nor `queued`:

```bash
curl -sS http://127.0.0.1:8080/api/admin/restore/<handle>
```

Successful completion has `state.status: "completed"` and `metadata` populated:

```json
{
  "metadata": {
    "backup_id": "ts-...",
    "location": "./data/.lifecycle/backup/ts-...",
    "restored_at_ms": 1760000000000,
    "size_bytes": 12345
  }
}
```

During restore the server enters maintenance mode and write APIs are blocked. If
restore fails after it starts, the server switches to read-only mode. If snapshot
integrity validation fails before the restore starts, the API returns an error
with code `RESTORE_INTEGRITY_MISMATCH`.

## Monitoring

Use health for a lightweight readiness check:

```bash
curl -sS http://127.0.0.1:8080/api/admin/health
```

Expected response:

```json
{
  "status": "ok",
  "message": "ready"
}
```

Use status for operational state:

```bash
curl -sS http://127.0.0.1:8080/api/admin/status
```

Important fields:

| Field | Normal value | Action when abnormal |
| --- | --- | --- |
| `overall_status` | `ok` | If `degraded`, inspect `read_only`, `maintenance`, `recovery_state`, and operation states |
| `read_only` | `false` | Writes are blocked; inspect `recovery_state.reason` and `restore_state.reason` |
| `maintenance` | `false` | Restore may be running; inspect `restore_state.status` |
| `recovery_state.outcome` | `success` | If `read_only` or `failed`, inspect `recovery_state.reason` |
| `backup_state.status` | `completed`, `queued`, or expected current operation | If `failed`, inspect `backup_state.reason` and retry backup after the cause is fixed |
| `restore_state.status` | `completed`, `queued`, or expected current operation | If `failed`, inspect `restore_state.reason` and retry restore from a verified snapshot |

Status responses also include `version`, `uptime_secs`, `last_recovery_at_ms`,
`last_backup_at_ms`, and `last_restore_at_ms` where available.

The HTTP API also exposes a JSON metrics summary for CLI/server commands:

```bash
curl -sS http://127.0.0.1:8080/api/admin/metrics
```

The response contains `qps`, `avg_latency_ms`, `p99_latency_ms`,
`memory_usage_mb`, and `active_connections`.

Prometheus-style metrics are exposed on the admin router at `/metrics` when
`metrics_enabled` is true. The server records spill counters as
`spill_bytes_total` and `spill_files_total` when SQL disk spill is used.

## First Response Diagnostics

1. Capture the current status and health responses.

```bash
curl -sS http://127.0.0.1:8080/api/admin/health
curl -sS http://127.0.0.1:8080/api/admin/status
```

2. Check the failing operation state.

```bash
curl -sS http://127.0.0.1:8080/api/admin/backup/<handle>
curl -sS http://127.0.0.1:8080/api/admin/restore/<handle>
```

Read `state.status`, `state.reason`, and the `x-correlation-id` response header
from the failed request. For JSON error responses, read `error.code`,
`error.message`, and `error.correlation_id`.

3. Check audit logs.

With defaults, audit events are JSON lines on stdout. For file output:

```toml
audit_log_enabled = true
audit_log_output = { type = "file", path = "./audit.log" }
```

Audit log entries include `event_type`, `actor`, `target`, `correlation_id`,
`timestamp`, and `details`. Match `correlation_id` with the failed HTTP
response.

4. Check storage snapshot files before retrying restore.

```bash
test -d ./data/.lifecycle/backup
test -f ./data/.lifecycle/backup/latest
cat ./data/.lifecycle/backup/latest
```

Use the printed snapshot path as the explicit `source` for restore retry:

```bash
curl -sS -X POST http://127.0.0.1:8080/api/admin/restore \
  -H 'content-type: application/json' \
  -d '{"source":"./data/.lifecycle/backup/ts-..."}'
```

5. If the server is in read-only mode after recovery or restore failure, do not
retry writes first. Inspect `recovery_state.reason` and `restore_state.reason`,
then retry restore from a known-good snapshot. Confirm recovery by polling
`/api/admin/status` until `overall_status` is `ok`, `read_only` is `false`, and
`maintenance` is `false`.
