# RCブランチ 週次サニタイザー検証

本ドキュメントは、RCブランチに対してサニタイザー・レーンを週1回の夜間実行で評価する運用方針を定めます。
リリースワークフローを軽量に保ちつつ、リリース候補の品質を継続的に検証することが目的です。

## 方針

- サニタイザー・レーンは **リリースワークフローの必須ゲートにしない**。
- サニタイザー・レーンは **RCブランチで週1回の夜間スケジュール実行**を行う。
- 失敗は **リリース阻止（release-blocking）扱い**とし、解決または明示的な承認まで解除しない。

## RCブランチの定義

RCブランチとは、リリース候補の評価用に作成するブランチで、命名規則は以下とする。

- 形式: `rc/<version>`（例: `rc/v0.5.0`）
- 追加RCが必要な場合: `rc/<version>-rcN`（例: `rc/v0.5.0-rc2`）
- 作成元: `main`（またはリリース準備用の基準ブランチ）

## 対象

週次RC実行では、以下のサニタイザーを実行する:

- macOS/Linux: TSAN + ASAN
- Linux: LSAN + MSAN

使用するスクリプト:

- `scripts/run-sanitizer-lane.sh`

## スケジュール

RCブランチに対し **週1回の夜間**に実行する。
cron はリリースサイクルに合わせて設定する（例: 毎週日曜 03:00 UTC）。

## アーティファクト

週次実行では以下を必ずアップロードする:

- `STRESS_REPORT_DIR`（サニタイザー・レポート）
- `STRESS_ARTIFACTS_DIR`（ストレス・アーティファクト）

トラブルシュートのため、保持期間はリポジトリ方針に従う。

## 手動実行

RC検証のための手動実行を許可する:

- `workflow_dispatch` を RC ブランチに対して実行
- スケジュール実行と同じ OS/サニタイザー構成とアーティファクト出力を維持する
